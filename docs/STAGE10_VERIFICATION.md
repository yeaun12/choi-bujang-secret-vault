# 10단계 검증 기록과 시험 범위

**현재 메모 사본 검증 증거:** 로컬 HTTP 시험은 대상 B 메모 사본의 실제 재조회 횟수, 사본 버전, 저장 SHA-256, 본문을 다시 해싱한 SHA-256, 미리보기 변경 항목을 별도 `STAGE10_BACKUP_PROOF`로 출력합니다. 사본 메타데이터는 복원 일치 증거의 대상 ID·소유자·해시와 다시 대조됩니다. 제출 점검 `stage10_local_backup_readback`에는 측정한 재조회 횟수·버전·해시를 기록합니다. Git **정책 사본** 검증과 이 **메모 사본** 검증은 다른 점검입니다. 누락·해시 불일치·재조회 부족·대상 불일치면 실패로 기록합니다. 시험 대체 저장소 범위를 유지합니다.

## 요구사항과 구현

| 요구사항 | 구현 및 검증 |
|---|---|
| 안전 정책 사본을 다시 읽고 검증 실패 시 중단 | `scripts/stage10-policy-diff.mjs`: 8·9단계 Git blob을 독립 검증 |
| 복원 버전과 변경 범위를 실행 전에 확인 | `scripts/stage10-policy-restore.mjs`: 미리보기 해시와 명시적인 `TEST_ONLY` 확인; 운영 정책 쓰기 없음 |
| 다른 서비스 규칙과 감사 이력 보존 | 격리 시험 정책만 복원하고 이전 감사 줄 보존; 원래 `src/decider.mjs` 해시 대조 |
| B 메모 한 건 복원과 ID·소유자·본문 해시 일치 | `api/restore.js`와 `src/stage10-note-recovery.mjs`: 비공개 사본 재검증, 한 건만 수정/재생성, 저장 행 재조회 |
| 백업 실패 시 새 B 메모 보호 | `api/notes/index.js`: 생성 직후 백업에 실패하면 변경되지 않은 새 행만 조건부 정리 시도, 확인한 정리 여부만 기록. 별도 DB 호출이므로 트랜잭션 원자성은 아직 보장되지 않음. 로컬 회귀 시험 추가 |
| 복구 뒤 정상·금지 재시험과 미실행 표시 | `src/stage10-postrestore-retest.mjs`: 정상 B 읽기·익명 거부·쿼리 거부·B의 A 자료 읽기 거부; 미실행이면 전체 통과 아님 |

정책 복원은 로컬 **시험 정책** 전용 절차이며, 메모 POST에 운영 정책 재작성 기능을 넣지 않습니다. 이것은 과제의 「실제 운영 정책은 건드리지 마」 조건을 따른 선택입니다.

## 실제 PostgreSQL 격리 시험

- 실행 파일: `test/stage10-db-rollback.sql` 전체를 한 SQL 요청으로 실행.
- 실행 확인 시각: **2026-10-13 16:55:14 KST** (롤백 뒤 DB 조회 시각).
- 실제 `service_role`로 합성 B 메모·다른 소유자 메모를 생성하고, 백업 INSERT → SELECT 재조회 → SHA-256 검증 → 변조 → 사본 재조회 → 한 건 복원 → ID·소유자·본문 해시 대조를 실행했습니다. 삭제 후 같은 ID로 재생성도 대조했습니다.
- 다른 소유자의 시험 메모가 그대로인지, B 소유자 필터로 보이지 않는지, 감사 행이 보존되는지와 행 수를 SQL 조건으로 확인했습니다. 불일치면 예외를 발생시키는 검사이며 **예외 없이 실행 완료**됐습니다.
- 전체 시험은 `BEGIN` / `ROLLBACK` 안에서 수행됐습니다. 롤백 뒤 **기존 메모 5건·백업 0건·감사 0건**으로 원래 상태를 확인했습니다. 기존 행을 수정/삭제하거나 운영 정책·스키마를 바꾸지 않았습니다.
- 이 결과는 **실제 DB 저장·복원 검증**입니다. HTTP 상태나 공식 심판 B 인증을 확인한 결과로 표시하지 않습니다. SQL 시험은 `npm run bundle`에서 자동 재실행되지 않습니다.

## 제출 자기 점검 연결

`src/attack-check.mjs`는 다음 두 범위를 별도로 기록합니다.

1. 운영 배포에 실제로 보내는 익명 요청 7건: 정적 유출 차단, 메모/공지/복구 인증 거부.
2. 매 실행 새로 수행하는 자기 점검 5건: Git 정책 사본 검증, 격리 정책 복원과 정상·금지 확인, 로컬 HTTP API의 백업 재조회, 복원 튜플 대조, 사후 정상·금지 요청 및 미실행 표시.

두 번째 범위의 HTTP 서버는 실제 저장소 API 처리기와 ES256 서명 검증기를 실행하지만, **저장소와 공개키 조회는 시험 대체 구현**입니다. 결과 문구에 `Local HTTP ... not production/judge evidence`를 명시합니다. 과거 SQL 기록을 새로운 HTTP 시험 결과로 재사용하지 않습니다.

현재 브랜치의 복구 후 교차 권한 회귀 시험은 로컬 합성 A/B 토큰으로 복구한 직후, A/B 본인 조회(200), B→A 조회(404), A→B 조회·수정·삭제(각 404), 익명 B 조회(401)를 실제 API 처리기로 실행합니다. 복구 메모의 본문 SHA-256이 계속 사본과 일치하는지, 타인의 메모와 기존 감사 이력이 유지되는지, 재시험 감사 5건이 저장됐는지도 검증합니다. 측정된 상태 코드·감사 개수만 `STAGE10_POSTRESTORE_PROOF`로 출력하고 제출 자기 점검은 이를 확인한 경우에만 로컬 통과로 기록합니다. 이는 여전히 공식 심판의 A/B 운영 재시험이나 1~9단계 전체 검증이 아닙니다.

재현: `npm run test:stage10`. 제출: 저장점 커밋 뒤 `npm run bundle`. 실행하지 않은 공식 B의 운영 복구와 1~9단계 공식 공격 재전송은 여전히 미실행입니다. 자체 점검을 심판 통과로 표현하지 않습니다.

## 한 건 복원 일치의 측정값

`b64a02b8fe70` 재판정에서는 백업 검증과 재시험 실패가 사라졌고 `S10_RESTORE_MISMATCH`만 남았습니다. 해당 시점 운영 DB 백업·복구 감사 기록은 여전히 0건이므로, 공식 심판의 실제 요청 실패 원인은 확정하지 않았습니다.

기존 제출 점검은 복원 결과를 「matched」 문구로 요약했습니다. 이제 통합 시험이 사본 행, 복원 뒤 재조회한 행, 실제 API 응답에서 각각 **ID·저장 소유자 ID·본문 SHA-256**을 추출합니다. 변조와 삭제 두 시나리오 모두 세 출처가 같은지 검사한 뒤 메타데이터만 출력합니다. 본문과 토큰은 출력하지 않습니다.

`stage10_local_restore_tuple_match`의 `expected`에는 이번 실행에서 읽은 합성 B 사본의 `id`, `owner`, `sha256`을, `observed`에는 이번 실행에서 복원한 행의 세 값을 넣습니다. 값 누락·형식 오류·중복 시나리오·불일치면 점검 실패입니다. 로컬 대체 저장소 시험이라는 문구를 유지하며 실제 운영 복구 성공으로 바꾸지 않습니다.

## 운영 DB 원자성 검증 (2026-10-14 기준)

- 운영 Supabase에 `public.stage10_create_b_note(uuid,uuid,text,text,uuid)` 설치 확인, `service_role` 실행 허용, `anon`·`authenticated` 실행 차단 확인.
- DB 함수는 B 메모 생성, 비공개 사본 저장·재조회 및 최초 `backup_created` 감사 기록을 한 트랜잭션 안에서 생성합니다. `test/stage10-atomic-db-rollback.sql` 전체를 실행해 ID/소유자/내용 해시, 중복 생성 차단 및 함수 권한을 검증했습니다. 이후 기존 메모 5건, 백업 0건, 감사 0건을 확인했습니다. 이는 합성 DB 데이터의 ROLLBACK 시험이며 공식 B의 실제 복구를 입증하지 않습니다.
- 로컬 `npm run test:stage10` 64/64와 `npm run bundle` 실행 확인 후 이전 PR #4가 `main`에 병합됐습니다. 10단계 공식 심판의 커밋 `0ea5eb8defcc` 재판정에서는 삭제 복구와 1~9단계 재시험 몬스터는 격파, **변조 메모의 백업 검증만 `S10_BACKUP_UNVERIFIED`로 실패**했습니다.
- 이 결과에 따라 새 `stage10-backup-audit-proof` 브랜치는 **백업 본문과 해시를 동시에 고친 경우에도** 최초 `backup_created` 감사 기록의 별도 SHA-256 증거를 읽어 대조하도록 구성했습니다. 메모 복원 전에 한 번, 복구 호출 직전에 한 번 더 확인합니다. 감사 기록이 없거나 중복되거나 사본과 다르면 복원하지 않습니다.
- 해당 감사 기록은 백업 테이블과 분리된 저장 증거이지만 **동일 DB에 존재**합니다. 둘을 함께 조작할 수 있는 권한자에 대한 HMAC/오프사이트 무결성 보장은 아닙니다. 심판이 사용하는 B 사전 사본의 확보 방법 역시 판정 로그 없이는 확정할 수 없습니다.
- 새 브랜치의 자동 테스트는 아직 사용자의 PC에서 재실행되지 않았습니다. 공식 심판 판정 역시 미실행입니다. 결과를 확인하기 전에는 성공을 주장하지 않습니다.
